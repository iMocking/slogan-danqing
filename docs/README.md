# 《仙途》游戏开发文档

> 古风水墨修仙 MMO · Godot 引擎实现方案
> 文档集版本：v1.0（初版规划）　创建日期：2026-10-06

本套文档由 `design/` 目录下的 UI 设计资产规划而来，用于把「一张张设计稿」翻译成
可执行的玩法设计、界面规格、技术方案与开发排期。

---

## 一、文档来源（设计资产盘点）

| 来源路径 | 内容 | 在文档中的作用 |
|---|---|---|
| `design/ui-01-login.png` ~ `ui-11-character-create.png` | 11 张 16:9 界面设计稿，2730×1536 | 界面布局与视觉的唯一依据 |
| `design/ui-design-showcase/仙途-UI设计稿.html` | 设计稿展示页，含每屏的文字说明 | 界面功能需求与元素清单来源 |

| `design/ui-assets-pack/assets/01~06-*.png` | 6 张素材图集总览，2730×1536 | 素材索引 |
| `design/ui-assets-pack/svg/**` | 约 64 个已切分 PNG 素材（含 SVG 源与 raw-png 对照） | 直接导入引擎使用 |

## 五、待决策问题（Open Questions）

| # | 问题 | 影响面 | 建议 |
|---|---|---|---|
| Q1 | **项目正式命名**：根目录 `README.md` 为《丹青劫》/ Project Danqing，设计资产为《仙途》。二者未统一。 | 全部文档、标题、资源命名前缀 | 尽快确认。本套文档暂以设计资产名 **《仙途》** 为准，若改用《丹青劫》需全局替换 |
| Q2 | **产品形态**：设计稿呈现完整 MMO 形态（拍卖行、世界地图、多门派）。是做联网 MMO，还是先做单机 / 弱联网的可玩版本？ | 技术选型、服务端工作量、排期 | 建议先做**单机可玩版本（Vertical Slice）**，网络层预留接口 |
| Q3 | **基准分辨率**：设计稿为 2730×1536。目标基准是 1920×1080 还是照搬 2730×1536？ | 全部 UI 尺寸、素材是否需要预缩放 | 见 [03-UI设计规范](03-UI设计规范.md) 3.1，建议基准 1920×1080 |
| Q4 | **素材版权**：UI 素材包与设计稿的商用授权范围？ | 能否上线 | 需确认授权书 |
| Q5 | **字体授权**：标题字体（毛笔书法体）与正文字体的商用授权 | 能否上线 | 建议改用开源可商用字体，见 06 章 |
| Q6 | **目标平台**：PC / 移动 / 双端？ | 布局安全区、输入方案、性能预算 | 设计稿为 16:9 横屏，建议 PC 优先 |
| Q7 | **玩法深度**：是否要做「以画入道 / 渡劫」的丹青特色玩法（见根 README 的设定）？ | 玩法差异化 | 建议作为后期特色系统，不进 MVP |

## 六、维护约定

- **状态标记**：✅ 已完成　🚧 进行中　⬜ 未开始　⚠️ 风险　❓ 待确认
- **变更流程**：设计稿变更 → 先更新 03 / 04 → 再同步 08 任务清单；玩法规则变更 → 更新 02。
- **单一事实来源**：界面布局以 `design/*.png` 为准；界面功能以 `04` 章为准；玩法规则以 `02` 章为准。
- **未标"待确认"的内容**均为可直接执行的结论；标 ❓ 的内容需人工拍板后再落地。
